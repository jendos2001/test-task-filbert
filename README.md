## Тестовое задание для ПКО Филберт

### Задание:
Надо будет реализовать следующий сценарий на тестовом сайте https://www.saucedemo.com/.

1. Авторизоваться.
2. Добавить несколько товаров в корзину.
3. Считать информацию о добавленных товарах (наименование, описание и цена) и сохранить её во внутренней структуре данных программы.
4. Удалить из сохранённой структуры данных один товар (на выбор разработчика), не выполняя пока никаких действий на сайте.
5. Перейти в корзину.
6. Привести содержимое корзины в соответствие с сохранённой структурой данных, удалив из корзины товар, исключённый на шаге 4.
7. Подтвердить выбор (Checkout).
8. Заполнить информацию на появившейся форме и нажать далее.
9. На странице подтверждения заказа получить и сохранить информацию о платеже (Payment Information), доставке (Shipping Information) и размере налога (Tax), после чего нажать Finish.
10. После успешного заказа скачать PDF (Generate PDF order).
11. Сохранить итоговые данные в формате XLSX.

Файл должен содержать:
* перечень товаров, оставшихся после шага 6, с указанием наименования, описания и цены;
* информацию о платеже (Payment Information);
* информацию о доставке (Shipping Information);
* размер налога (Tax);
* итоговую стоимость заказа с учетом налога (Total).
Структуру и оформление XLSX-файла разработчик определяет самостоятельно. При открытии файла должно быть однозначно понятно, какие данные представлены и к чему они относятся.

### Запуск программы
1. Клонировать репозиторий командой `git clone https://github.com/jendos2001/test-task-filbert.git`
2. Задать переменные среды в файле `.env.project`. В самом файле уже заданы готовые переменные, с которыми программа работает.
3. Собрать приложение командной `sudo docker compose --env-file .env.project build`
4. Запустить приложение командой `sudo docker compose --env-file .env.project up -d`
5. После выполнения работы в текущей директории появятся файлы с базой данных в директории `Databases`, сформированные отчёты в директории `Downloads` и логи в директории `logs`.
6. Для повторного запуска можно использовать команду `sudo docker exec -it parser_container python3 main.py`
7. Для того, чтобы дать права доступа (на Linux) можно использовать команду `sudo chmod -R 777 ./Databases/ ./Downloads/ ./logs/`



### Выполнение
Код был написан без помощи ИИ.
1. Для авторизации была изучена структура страницы через инструменты разработчика. Были найдены ID полей для ввода логина и пароля, а также кнопки для авторизации. Эти поля былы заполнены и нажата кнопка входа.
2. Была изучена структура с товарами. В инстументах разработчика был найден div, который содержит все представленные товары. Были выбраны случайные элементы и добавлены в корзину.
3. Случайные элементы были добавлены в базу sqlalchemy.
4. Случайным образом был удалён один товар из текущих.
5. С помощью инструментов разработчика была найдена кнопка перехода в корзину, затем был совершён переход туда.
6. С помощью инструмента разрабочика был найден div, где содержатся добавленные товары в корзину. В этом элементе была произведена итерация по элементам, чтобы найти удалённый товар на шаге 4.
7. С помощью инструментов разработчика была найдена кнопка подтверждения заказа.
8. С помощью инструментов разработчика были найдены ID полей для ввода данных. Эти поля былы сохранены в память программы, заполнены и нажата кнопка далее.
9. С помощью инструментов разработчика были найдены ID полей для ввода данных. Эти поля были сохранены в память программы, заполнены. После заполнения полей в базу данных была занесена информация о заказе, а также заказ был связан с товарами, которые присутствуют в заказе.
10. С помощью инструментов разработчика была найдена кнопка, генерирующая отчёт, а затем нажата.
11. Был сгенерирован отчёт в формате xlsx исходя из данных заказа. Данные для формирования отчёта получались из базы данных. В отчёте указана информация о доставке, данные о товарах, сумма без доставки, стоимость доставки, стоимость на сайте и расчитанная стоимость исходя из суммы товаров и суммы доставка. Была добавлена ячейка-световой индикатор, которая заливается зелёным, если стоимость на сайте и расчитанная стоимость равны, и красным, если стоимости не равны.

- Все приложение обёрнуто в докер-контейнер для более удобного запуска. Было настроено логгирование в файл для удобства.

#### Возникшие сложности
-  В последнем шаге сценария на сайте при нажатии на кнопку генерации PDF-отчёта драйвер закрывался и отчёт не всегда успевал скачаться. Было выяснено, что во время скачивания кнопка меняет название на "Generating", и после скачивания возвращается в исходное состояние. Поэтому было решено дожидаться, пока текст на кнопке вернется в исходное состояние, и только после этого закрывать драйвер.
- В докере selenium и Chrome работают хуже, чем на локале. Пришлось настраивать параметры для драйвера, чтобы он смог работать в докере.
- Решение проблем происходило через поиск ошибок на специализированных сайтах, например, stackoverflow, а также с помощью чтения документации.
